## 3. Initial Platform Setup

This section covers the one-time setup of the core platform infrastructure, including the dispatch namespace, the dispatch Worker, and the platform management API.

### 3.1. Create CloudFlare Resources

Before deploying the Workers, you need to create the necessary CloudFlare resources (KV namespaces and a D1 database).

1.  **Create KV Namespaces**:

    ```bash
    # For tenant configuration
    npx wrangler kv:namespace create TENANT_CONFIG

    # For rate limiting
    npx wrangler kv:namespace create RATE_LIMITS
    ```

    Take note of the `id` for each namespace, as you will need them for the `wrangler.toml` configuration.

2.  **Create D1 Database**:

    ```bash
    npx wrangler d1 create flarecog_analytics
    ```

    Take note of the `database_id`, which you will need for the `wrangler.toml` configuration.

### 3.2. Create Dispatch Namespace

The dispatch namespace is the container for all tenant-specific user Workers.

```bash
npx wrangler dispatch-namespace create flarecog
```

This command creates a dispatch namespace named `flarecog`.

### 3.3. Configure and Deploy the Dispatch Worker

The dispatch Worker is the central router for the platform.

1.  **Navigate to the dispatch Worker directory**:

    ```bash
    cd flarecog-platform/dispatch-worker
    ```

2.  **Update `wrangler.toml`**:

    Open `wrangler.toml` and replace the placeholder IDs with the actual IDs of the resources you created in step 3.1.

    ```toml
    # ... (other configuration)

    [[kv_namespaces]]
    binding = "TENANT_CONFIG"
    id = "<YOUR_TENANT_CONFIG_KV_ID>"

    [[kv_namespaces]]
    binding = "RATE_LIMITS"
    id = "<YOUR_RATE_LIMITS_KV_ID>"

    [[d1_databases]]
    binding = "ANALYTICS_DB"
    database_name = "flarecog_analytics"
    database_id = "<YOUR_ANALYTICS_DB_ID>"
    ```

3.  **Deploy the dispatch Worker**:

    ```bash
    npx wrangler deploy
    ```

### 3.4. Configure DNS

To route traffic to your dispatch Worker, you need to configure a DNS record for your custom domain. Create a wildcard `A` or `CNAME` record that points to your dispatch Worker. For example, if your domain is `flarecog.ai`, you would create a record for `*.flarecog.ai`.

## 4. Tenant Provisioning

This section describes how to provision a new tenant on the FlareCog platform. This process involves creating tenant-specific resources and deploying a user Worker to the dispatch namespace.

### 4.1. Create Tenant-Specific Resources

For each new tenant, you need to create a dedicated D1 database and KV namespace.

1.  **Create D1 Database**:

    ```bash
    npx wrangler d1 create flarecog_<tenant_id>
    ```

2.  **Create KV Namespace**:

    ```bash
    npx wrangler kv:namespace create ATOM_CACHE_<tenant_id>
    ```

    Replace `<tenant_id>` with the unique identifier for the new tenant (e.g., `acme`).

### 4.2. Configure and Deploy the User Worker

1.  **Create a `wrangler.toml` file for the tenant**:

    From the `flarecog-platform/user-worker-template` directory, create a copy of `wrangler.template.toml` and name it `wrangler.<tenant_id>.toml`.

2.  **Update the tenant-specific `wrangler.toml`**:

    Open the new `wrangler.<tenant_id>.toml` file and replace the placeholders with the tenant-specific information.

    ```toml
    name = "flarecog-user-<tenant_id>"
    # ... (other configuration)

    [[d1_databases]]
    binding = "COGNITIVE_DB"
    database_name = "flarecog_<tenant_id>"
    database_id = "<TENANT_D1_DATABASE_ID>"

    [[kv_namespaces]]
    binding = "ATOM_CACHE"
    id = "<TENANT_KV_NAMESPACE_ID>"

    [vars]
    TENANT_ID = "<tenant_id>"
    TENANT_NAME = "<tenant_name>"
    ```

3.  **Deploy the user Worker to the dispatch namespace**:

    ```bash
    cd flarecog-platform/user-worker-template
    npx wrangler deploy --config wrangler.<tenant_id>.toml --dispatch-namespace flarecog
    ```

    This command deploys the user Worker with the specified configuration to the `flarecog` dispatch namespace. The dispatch Worker can now route requests for this tenant to the newly deployed user Worker.
